# 校園選課與活動管理系統
## 第 5 週進度報告

### 一、研究動機與目標
本專題旨在開發一套校園選課與活動管理系統，協助學生進行課程管理、選課衝突檢查、課表查詢與活動配置。依照作業規範，系統以 Python 命令列應用程式為核心架構，所有核心功能必須以可獨立測試的函式實作，並避免使用全域變數傳遞資料。

第 5 週的任務重點為需求整理、規格確認與最小專案骨架建立，目的是在後續功能實作之前，先行確立共用資料格式、模組責任分工與可擴充架構，避免後續各功能模組因接口不一致而造成整合問題。

### 二、需求分析與規格整理
本週已依照 README.md、assignment.txt、implementation-guide.txt 與 weekly-plan.txt 內容，整理系統需求與未決規格。整理結果可分為三部分：

1. 老師明確要求
   - 系統採用 Python 開發，命令列介面即可。
   - 核心功能必須以可獨立測試的函式實作。
   - 不得依賴 input() 或全域變數傳遞資料。
   - 須使用 Git 進行版本管理。
   - F1～F6 為期中功能範圍，F7～F11 為後續功能。

2. 團隊待確認規格
   - 時間表示方式：星期 1～7、節次 1～9、a、b、c。
   - 課表矩陣固定為 7 天 × 12 節次。
   - 空堂判定與跨日查詢規則需一致。
   - 選課紀錄、資料更新方式與錯誤處理形式需統一。
   - 偏好條件與硬限制需分開處理。

3. 團隊建議設計
   - 使用分層架構，各模組明確負責資料、驗證、儲存與規劃。
   - 使用統一資料模型避免各模組自行定義不同格式。
   - 先訂定函式介面，再逐步實作功能，確保後續整合順暢。

---

### 三、專案架構設計
本週已建立最小專案骨架，系統主要由以下模組組成：

- main.py：程式入口
- campus_planner/models.py：資料模型
- campus_planner/validation.py：資料驗證與衝突檢查
- campus_planner/data_store.py：資料儲存與載入
- campus_planner/planner.py：示例資料與規劃摘要
- campus_planner/timetable.py：課表矩陣與空閒時段
- tests/test_minimal_contract.py：最小測試基線
- data/sample_school_data.json：測試範例資料

本架構採用分層設計原則，讓每個模組具有明確職責：
- 資料模型層處理資料結構。
- 驗證層處理欄位正確性與衝突檢查。
- 儲存層處理 JSON/CSV 資料讀寫。
- 規劃層負責樣例資料和摘要輸出。
- 課表層負責課表矩陣與空閒時段計算。

此架構能降低後續功能擴充時的整合風險，並符合作業要求中「核心函式可獨立測試」的規範。

---

### 四、資料格式與介面規範
為了使後續模組能共同協作，本週先統一基本資料格式與函式介面，主要包含：

- 課程：代號、名稱、學分、必選修、教師、容量、教室、時段。
- 學生：學號、姓名、系級、已選課程、學分上限。
- 教室：代號、容量、設備、建築物。
- 活動：代號、名稱、日期、時間、預計人數、需求與場地。

資料驗證函式主要包括：
- validate_course()
- validate_student()
- check_time_conflict()
- check_slot_list_conflict()
- evaluate_enrollment()

資料儲存函式主要包括：
- save_school_data()
- load_school_data()

課表函式主要包括：
- build_weekly_matrix()
- place_course_in_timetable()
- summarise_timetable()

這些函式均以明確輸入與輸出形式設計，避免後續模組依賴全域狀態或人工操作。
