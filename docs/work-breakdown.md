# 工作分解與分工建議（第 5 週）

## 1. 六人角色

| 角色 | 主要責任 | 期中重點 |
| --- | --- | --- |
| A | 組長、整合、儲存載入、主流程 | F6、主程式、Git 管理 |
| B | 資料管理與需求分析 | F1 課程/學生/教室資料 |
| C | 選課限制與篩選 | F2、F5 衝堂與規則 |
| D | 課表與活動 | F3、F4 課表與場地 |
| E | 搜尋與效能 | F7、F8 最佳課表與比較 |
| F | 路徑與事件 | F9、F10 移動與重規劃 |

## 2. 第 5 週具體任務

- A：建立 Git、README、資料夾、執行入口、測試骨架
- B：確認資料模型、學分、代號、時段規則
- C：定義選課限制與衝突判斷邏輯
- D：確認課表矩陣與活動資料定義
- E：整理搜尋輸入、必要條件與偏好設定
- F：整理地圖資料與事件情境定義

## 3. 協作規範

- 每個模組需有人主責，也需由其他成員 Review。
- 檢查與測試必須由非原開發者檢驗，至少一次。
- 每人需保留個人工作紀錄與 AI 協作紀錄。
- 第 10 週起新增功能必須先寫測試，保留 Red/Green/Refactor 歷程。

## 4. 最小可交付內容

- 需求規格 v1
- Use Case
- 架構圖 v1
- 資料格式定義
- 基本測試基線
- 可執行 Python 程式入口

## 5. 風險與緩解

- 資料格式不統一：先定義共用 dataclass 與 JSON 結構。
- 功能彼此耦合：先讓核心函式接收明確參數，不使用全域狀態。
- 測試不足：先準備正常、邊界、錯誤三類測試，避免後期補強太晚。
