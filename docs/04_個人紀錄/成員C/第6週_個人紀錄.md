## 四、程式理解說明（以 test_cancel_course_drops_students_then_deletes 為例）

<!-- widths: 20,80 -->
| 項目 | 說明 |
| --- | --- |

| Process | 呼叫 cancel_course(catalog, "CS101")。系統先替所有選修的學生退選，隨後將 CS101 從系統中刪除。 |

## 六、AI 協作紀錄

<!-- widths: 20,80 -->
| 項目 | 內容 |
| --- | --- |
| 使用的 AI | Gemini |
| 問題 | 針對無效學分與非法節次的錯誤測試案例過於重複，希望優化測試程式結構。 |
| Prompt | 我正在用 pytest 寫單元測試，需要測試遇到多種無效學分輸入（如 0, -3, 3.5, True, '3'）時是否回傳錯誤。有什麼寫法能不用把同一個斷言複製五次？ |
| AI 建議摘要 | 建議使用 @pytest.mark.parametrize 裝飾器。可將測試變數定義為陣列，pytest 會自動輪流帶入測試函式執行並獨立計算結果。 |
| 是否採納 | 完全採納 |
| 採納理由 | 大幅減少程式碼行數，且在 CLI 執行 pytest -q 時，能清晰看到每個邊界值獨立標示為通過，便於後續擴充使用。 |
| 驗證方式 | 實際套用於 test_f1_catalog.py，並暫時關閉 validation.py 型別檢查，確認 pytest 準確報出特定參數（如 True）的失敗，證實邏輯有效。 |
