## 四、程式理解說明

我選 catalog_from_dict，因為它負責把存檔的 JSON 讀回程式，和我負責的 F6 資料儲存與載入直接相關，也是 main.py 啟動時第一個用到的函式。

<!-- widths: 20,80 -->
| 項目 | catalog_from_dict(data)（campus_planner/data_manager.py） |
| --- | --- |
| Input | 一個 dict，也就是 JSON 檔讀進來的內容，裡面有 classrooms、courses、students 三個清單，每個清單的每一筆都是一般的 dict。 |
| Process | 1. 先建立一個空的 SchoolCatalog。<br>2. 依「教室 → 課程 → 學生」的順序處理，每一筆先用 classroom_from_dict 等函式轉成資料物件，再交給 add_classroom、add_course、add_student 新增。<br>3. 這樣讀檔和手動新增會經過同一套驗證，不會有「從檔案讀進來就不檢查」的漏洞。<br>4. 學生一定放最後，因為新增學生時要檢查他的已選課程是否存在，課程必須先載入。 |
| Output | 回傳兩個東西：catalog（成功載入的所有資料）和 errors（被略過的資料與原因）。<br>例如範例檔載入後是 20 門課、15 名學生、5 間教室，errors 為空清單。 |
| Boundary／Error | 1. 某一筆缺欄位：轉換時丟出 ValueError，只略過這一筆並記錄，例如「課程 BAD1: 課程資料缺少欄位…」。<br>2. 某一筆欄位不合法：例如學分是 0，add_course 回傳錯誤，記錄「課程 BAD2: 學分必須為正整數」，其他 20 門課照常載入。<br>3. 學生選了不存在的課：該學生不會被載入，並記錄原因。<br>4. 某個清單沒有出現在檔案中：視為空清單，不會出錯。<br>5. 整個檔案不是合法 JSON：不會進到這個函式，由 load_catalog 先攔下，回傳空的 catalog 和「JSON 格式錯誤」訊息。<br>重點是一筆壞資料不會讓整個程式當掉，對應老師 F6「不得因單一筆資料格式錯誤造成程式異常終止」的要求。 |

### 個人反思與後續規劃

本週發現，文件與程式一旦分散在不同資料夾，很容易出現失效連結或互相矛盾的分工描述；集中整理並以腳本檢查連結，比人工逐一確認可靠。AI 可以很快產生 F1 初版程式與測試，但它也會寫錯，這次就是靠測試才發現參數衝突，因此 AI 產生的內容必須經過測試與成員理解後才能提交。

接下來會追蹤 B 修正 Code Review 提出的問題並重新驗證，並補齊第 6 週團隊繳交文件中的 Git、Review 與會議紀錄。
