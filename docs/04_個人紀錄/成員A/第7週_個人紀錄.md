## 四、程式理解說明

我選 check_enrollment，因為它是 v2 主程式示範 F2 時呼叫的核心函式，也用到我本週負責的活動資料。

<!-- widths: 20,80 -->
| 項目 | check_enrollment(catalog, student_id, course_id)（campus_planner/enrollment.py） |
| --- | --- |
| Input | 所有資料 catalog、學號、欲加選的課程代號。 |
| Process | 1. 先確認學生與課程存在、學生沒有選過這門課。<br>2. 把課程的時段和學生已選課程、已參加活動的時段比對；同時檢查這門課的教室在同時段有沒有被別的課程或活動用掉。<br>3. 同一門課在同一天的連續衝突合併成一筆，全部依星期、節次排序。<br>4. 計算加選後學分是否超過上限，以及選修人數是否已達人數上限。<br>5. 全部的結果都放進 CheckResult，不會在第一個錯誤就停下來，也不修改任何資料。 |
| Output | CheckResult：conflicts 是排好序的時段衝突，errors 是學分、額滿等其他問題，另有目前學分、加選後學分、學分上限；兩者都是空的時 ok 為 True。 |
| Boundary／Error | 1. 學生或課程不存在：直接回傳錯誤，不做後續檢查。<br>2. 加選後學分剛好等於上限：可以通過，超過才拒絕。<br>3. 相鄰節次（第 4 節與第 5 節）不算衝突，只有同星期同節次才算。<br>4. 額滿以實際選修人數判斷，學生自己選了幾門課不影響（上週缺陷 D1 的修正）。 |
