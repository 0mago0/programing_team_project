# Use Case（簡版）

## 1. 角色

- 學生：查詢課程、選課、查看個人課表
- 教務助理：新增與維護課程與教室資料
- 系統管理者：儲存/載入資料、查看測試報告

## 2. 主要場景

### Use Case A：新增課程
1. 教務助理輸入課程代號、名稱、學分、必選修、教師、容量、教室與時段。
2. 系統驗證資料格式與重複代號。
3. 若合法，寫入課程清單；否則回傳錯誤列表。

### Use Case B：學生加選
1. 學生提供學號與想加選的課程代號。
2. 系統檢查學生是否存在、課程是否存在、是否衝堂、是否額滿、是否超過學分上限。
3. 若全部通過，更新學生已選課程；否則回傳所有衝突。

### Use Case C：查詢課表
1. 學生輸入學號與日期區間。
2. 系統彙整課程和活動時段。
3. 回傳 7×12 課表、空閒區段與每日統計資訊。

### Use Case D：活動配置
1. 活動管理者輸入活動名稱、日期、時間與場地需求。
2. 系統篩選可用教室並檢查是否衝突。
3. 若無可用教室，回傳未滿足條件。

### Use Case E：儲存與再載入
1. 管理者執行儲存。
2. 系統寫出 JSON/CSV 檔案。
3. 重新啟動後再載入，若資料格式錯誤只回報錯誤並保留穩定狀態。

## 3. 例外行為

- 重複代號：拒絕新增並回報錯誤。
- 非法時段：拒絕並列出不合法節次。
- 課程已有人選：不允許直接刪除，需先退選。
- 無法滿足學分下限：輸出候選課程不足的原因。

## 4. 驗收重點

- 所有 Use Case 必須能透過單元測試驗證。
- 錯誤消息要明確、可自動判斷。
- 資料格式需一致，避免因表格內容差異導致系統崩潰。
