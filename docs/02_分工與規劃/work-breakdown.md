# 工作分解與分工建議（第 5 週）

## 1. 五人角色

| 角色 | 主要責任 | 期中重點 |
| --- | --- | --- |
| A | 組長、整合、儲存載入、主流程 | F6、主程式、Git 管理 |
| B | 資料管理與需求分析 | F1 課程/學生/教室資料 |
| C | 選課限制、篩選與動態事件 | F2、F5、F10 衝堂、規則與事件重規劃 |
| D | 課表、活動與路徑 | F3、F4、F9 課表、場地與最短路徑 |
| E | 搜尋與效能 | F7、F8 最佳課表與比較 |

## 2. 第 5 週具體任務

- A：建立 Git、README、資料夾、執行入口、測試骨架
- B：確認資料模型、學分、代號、時段規則
- C：定義選課限制、衝突判斷邏輯與事件情境
- D：確認課表矩陣、活動與地圖資料定義
- E：整理搜尋輸入、必要條件與偏好設定

## 3. 協作規範

- 每個模組需有人主責，也需由其他成員 Review。
- 檢查與測試必須由非原開發者檢驗，至少一次。
- 每人需保留個人工作紀錄與 AI 協作紀錄。
- 第 10 週起新增功能必須先寫測試，保留 Red/Green/Refactor 歷程。

## 4. 最小可交付內容

- 需求規格 v1
- Use Case
- 架構圖 v1
- 資料格式定義
- 基本測試基線
- 可執行 Python 程式入口

## 5. 風險與緩解

- 資料格式不統一：先定義共用 dataclass 與 JSON 結構。
- 功能彼此耦合：先讓核心函式接收明確參數，不使用全域狀態。
- 測試不足：先準備正常、邊界、錯誤三類測試，避免後期補強太晚。

現行五人分工：A 主責 F6 與整合；B 主責 F1；C 主責 F2、F5、F10；D 主責 F3、F4、F9；E 主責 F7、F8。F11 全員參與，由 A 統整。Review：A → B → C → D → E → A。
