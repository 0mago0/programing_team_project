## 四、AI 有幫助與仍需自己判斷的地方

<!-- widths: 50,50 -->
| AI 有幫助的地方 | 仍需團隊自己判斷的地方 |
| --- | --- |
| 快速產生初版程式與大量測試案例的骨架 | 規格未明訂的規則（R1～R31）要由團隊開會決定 |
| 整理文件格式、檢查連結與一致性 | AI 產生的程式要讀懂、實際執行、看測試結果才能採用 |
| 提供測試寫法（如 parametrize）與錯誤訊息的可能原因 | 資料是否合理、是否在讓資料配合程式 |
| 協助列出 Code Review 的可疑之處 | 哪些疑點真的是問題，要以執行結果確認；Review 的回應不能由 AI 代填 |

## 五、團隊使用原則

- AI 產生的程式只當初版，由負責成員閱讀、執行測試後，以本人帳號提交，並在個人紀錄寫明。
- 每一項 AI 建議都要有驗證方式：測試、實際執行或邏輯分析。
- 不由 AI 代填 Code Review 回應、會議內容或個人反思。
- B、D 請於下週補交 AI 協作紀錄；沒有使用 AI 時註明「本週未使用」。
